当前本地候选源码为 **3.3.3 / versionCode 13**：新增指定版本的芒果 TV 与 CIBN 酷喵启动入口，尚未安装到电视。已安装且完成一次覆盖安装与背景切换实机验证的版本为 3.3.2/code12。两者的构建、安装与功能验收分别记录。

## 本地工具

| 工具 | 要求 |
| --- | --- |
| Python | 3.9+，标准库 |
| JDK | 本轮使用已有 JDK17，调用 javac／java |
| Android 平台 | API22 的 `android.jar` |
| Android build-tools | aapt、zipalign、`lib/d8.jar`；本地已知工具为 34 系列 |

应用使用 Android／JDK 标准 API 及 Android 内置 `org.json`，没有随源码附带 SDK／JDK 二进制或自动下载依赖。保留 minSdk21、targetSdk22；这不是现代 Android TV 适配或全设备兼容保证。

## unsigned 构建

```text
python tools/build_unsigned.py --java-home <existing-jdk-17> --android-jar <existing-api22-android.jar> --build-tools <existing-build-tools>
```

工具路径由调用者传入，不将本机绝对路径写入仓库。构建流程为 aapt 资源处理 → javac Java8 目标 → D8 minAPI21 → 写入 DEX → zipalign 与包信息检查。

只将源码、XML 与资源逐项加入构建白名单；新增内置照片也须通过该白名单。不得自动打包整个旧 assets 目录、位置配置、偏好、缓存或示例文件。输出与仅本地日志留在 `build/`，不公开日志、私人产物或签名材料。

此入口只生成 unsigned APK，不负责签名、安装或修改设备。Unsigned APK 不能直接覆盖已有应用。

3.3.3 的 `tests/test_verified_launch.py` 使用现有 JDK 编译真实入口策略与最小 Android API 替身，检验版本边界、参数类型、组件权限、缺包回退和重复按键／稍后热启动。它不模拟第三方应用实际广告或播放。电视覆盖更新须先使用与已装 3.3.2 相同的签名，并在安装前核对包名、code13、签名兼容与私人设备资源差异；本地 unsigned 包不能直接安装，也不包含旧私人 UI 资源。

## 本机开机默认问题（2026-10-27）

用户反馈开机先到 TCL 桌面，随后按 HOME 键可回蓝境，界面没有「始终」选项。只读检查确认仍安装 3.3.2/code12、HOME 候选组件存在，未发现持久 HOME 首选记录。该记录为空不等于 HOME 键无效，也不能确定此前是否曾保存或重置某个首选值；厂商开机流程与默认策略待查。

源码中的开机接收器只处理壁纸通知，不负责设置系统默认桌面。已有安装、切图和背景模式恢复结果不能替代开机默认行为验证；本轮没有重启或冷开机测试，也不将本机现象概括为所有设备的通病。

## 安装与恢复说明

仓库没有签名发行包。覆盖安装取决于相同应用身份、版本规则与签名连续性；这里不提供尚未在目标设备验证的通用命令。

“恢复先前背景模式”只恢复背景来源／模式，不等于精确恢复上一张照片，也不等于卸载或返回原厂桌面。系统默认桌面、数据与安装回退需要另外的设备验证记录。
